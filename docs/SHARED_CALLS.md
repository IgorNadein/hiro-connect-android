# Общий журнал 0.7

«Звонки → Журнал» загружает данные HI-RO Server, а не Baresip.callHistory.
Доступны поиск по номеру/имени/менеджеру, пропущенные, следующие страницы,
карточка, запись и общая заметка. Старая история не удаляется: кнопка
«История на этом смартфоне» открывает прежние локальные записи.

Все авторизованные видят журнал. Сервер отдельно проверяет manager/admin для
аудио, редактирования заметок и участия. Разрешения приходят в capabilities;
отсутствующие разрешения трактуются как запрет. Аудио загружается только после
«Слушать», с Bearer, без перенаправлений, максимум 256 МиБ, в приватный временный
кеш. Кеш очищается при выходе с экрана, выходе из аккаунта и старте приложения.
Автоматического воспроизведения, публичной ссылки на WAV и выгрузки личных
записей смартфона нет. Ошибка сервера не отображается как пустая история.

Заметка сохраняется с If-Match note_revision; 412 не стирает черновик.
После обновления карточки показывается текущая серверная заметка для сравнения.
Навигация предупреждает о несохранённом тексте.

«Сейчас» показывает соединённые разговоры, «Очередь» — ожидающие внешние каналы
по актуальному снимку АТС, обновляемому раз в три секунды в открытом экране.
«Участвовать» требует подтверждения. Сервер запрашивает обратный вызов только
в собственную аутентифицированную SIP-сессию. Менеджер отвечает на него, чтобы
участвовать голосом. 202 означает запрос, а не доказанное подключение/аудио.
Скрытого режима прослушивания нет; доступ к журналу сам по себе не даёт участия.

Бэкенд должен быть обновлён и PHONE_GATEWAY_JOURNAL_ENABLED=true.
Без модуля отображается явная ошибка, не демонстрационные звонки.
Старые WAV без CDR доступны как архив без выдуманных номеров/участников.
Отсутствующая серверная запись не заменяется локальной и не получает кнопку
прослушивания. Запись всех исходящих и сроки хранения этим изменением не включены.
Связь истории с резюме ИИ ещё не реализована и явно отмечена в карточке.

Клиентские DTO не содержат introduced_by_user_id/name. Nullable-атрибуция
сохраняется сервером, но не отображается в списке, карточке или подтверждении.

Проверки: обычные unit tests, opt-in NativeSharedCallsTest вместе с прежними
UI-тестами, assembleRelease и lintRelease. Сценарии используют синтетические
данные и не звонят реальным абонентам. Физический звук, callback и маршрутизацию
на реальных устройствах нужно принять отдельным разрешённым тестовым звонком.
