# Подключение к self-hosted серверу

HI-RO Connect должен подключаться к серверу, выбранному организацией или самим пользователем. Центральный сервер разработчика не является обязательным.

## Текущее состояние

Приложение использует стандартный SIP-аккаунт HI-RO Server:

- адрес сервера;
- внутренний номер;
- пароль;
- TCP transport.

Данные вводятся локально и не поставляются внутри APK.

## Целевой первый запуск

1. Пользователь вводит адрес домашнего сервера.
2. Приложение запрашивает `/.well-known/hiro/client`.
3. Сервер сообщает API и доступные способы входа.
4. Пользователь проходит локальный вход, OIDC, Keycloak или корпоративную авторизацию.
5. Сервер выдаёт ограниченный токен устройства и настройки телефонии.
6. Приложение показывает доступные очереди и шлюзы.

Пароль пользователя не должен превращаться в SIP-пароль и не должен передаваться другому серверу. SIP/WebRTC credentials выдаются как отдельные короткоживущие данные сессии.

## Федерация

Клиент всегда входит на свой домашний сервер. Если администратор включил beta-федерацию, домашний сервер самостоятельно договаривается с разрешённым партнёром. Приложению не выдаются серверные ключи федерации.

Полная модель описана в [HI-RO Protocol](https://github.com/IgorNadein/hiro-protocol).
