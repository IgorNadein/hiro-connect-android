# Подключение к self-hosted серверу

HI-RO Connect должен подключаться к серверу, выбранному организацией или самим пользователем. Центральный сервер разработчика не является обязательным.

## Текущее состояние

Начиная с версии `0.3.0`, приложение использует постоянную серверную сессию устройства:

1. пользователь вводит адрес своего HI-RO Server;
2. приложение читает `/.well-known/hiro/client`;
3. для локального password-провайдера вызывает объявленный `login_endpoint`;
4. получает короткий access token и бессрочный отзываемый device token;
5. проверяет выданную сессию через `/api/v1/auth/me`;
6. шифрует оба токена при помощи Android Keystore;
7. автоматически обновляет access token через объявленный `refresh_endpoint`.

Пароль существует только в памяти на время запроса и не сохраняется. Истечение короткого access token, выключение телефона и отсутствие сети не завершают вход. Сессия удаляется локально только после явного выхода или ответа сервера о её отзыве. Клиент запрещает discovery перенаправлять пароль или токены на другой origin. Release-сборка принимает только HTTPS.

Телефонный транспорт пока продолжает использовать отдельный стандартный SIP-аккаунт HI-RO Server:

- адрес сервера;
- внутренний номер;
- пароль;
- TCP transport.

Данные вводятся локально и не поставляются внутри APK.

## Первый запуск

1. Пользователь вводит адрес домашнего сервера.
2. Приложение запрашивает `/.well-known/hiro/client`.
3. Сервер сообщает API и доступные способы входа.
4. В текущей версии пользователь проходит локальный вход по логину и паролю.
5. Сервер выдаёт короткоживущий access token и постоянную сессию устройства.
6. Приложение показывает рабочее место и локально настроенный SIP-аккаунт.

Пароль пользователя не превращается в SIP-пароль и не передаётся другому серверу. Постоянная сессия не имеет временного срока окончания; сервер может отозвать её отдельно для каждого устройства. Автоматическая выдача отдельных SIP/WebRTC credentials, OIDC и LDAP относятся к следующему этапу.

## Локальная debug-проверка через USB

Рабочая release-сборка запрещает незашифрованный HTTP. Для разработки debug-вариант разрешает HTTP, а сервер можно безопасно оставить на loopback компьютера и пробросить через ADB:

```bash
adb reverse tcp:8788 tcp:8788
```

В приложении указывается `http://127.0.0.1:8788`. Это исключение существует только в debug manifest и не попадает в release APK.

## Федерация

Клиент всегда входит на свой домашний сервер. Если администратор включил beta-федерацию, домашний сервер самостоятельно договаривается с разрешённым партнёром. Приложению не выдаются серверные ключи федерации.

Полная модель описана в [HI-RO Protocol](https://github.com/IgorNadein/hiro-protocol).
