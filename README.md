# HI-RO Connect

Android-приложение рабочего места оператора для HI-RO Phone Gateway. Телефон менеджера регистрируется на локальном шлюзе по SIP и получает входящие вызовы через штатный Android Telecom UI, в том числе при заблокированном экране.

## Экосистема

| Компонент | Репозиторий |
| --- | --- |
| Самохостинговый сервер и телефонный шлюз | [HI-RO Server](https://github.com/IgorNadein/hiro-server) |
| Android SMS-шлюз | [HI-RO Messages](https://github.com/IgorNadein/hiro-messages-android) |
| Спецификация авторизации и федерации | [HI-RO Protocol](https://github.com/IgorNadein/hiro-protocol) |

Архитектура не требует центрального аккаунта HI-RO: пользователь выбирает сервер своей организации, приложение получает доступные способы входа через discovery, а сервер самостоятельно проверяет учётные данные. SIP-аккаунт остаётся отдельным транспортным credential и не совпадает с паролем пользователя. Подробности — в [документации подключения](docs/SERVER_CONNECTION.md).

## Возможности

### Обновлённый нативный интерфейс (0.6.2)

Единая визуальная система по утверждённому макету: спокойные поверхности, синий
акцент, аватары, читаемые статусы и четыре постоянных раздела. Переработаны вход,
журнал с поиском и фильтром пропущенных, клиенты и личные контакты, список SMS,
набор номера, карточки входящего/исходящего вызова и управление разговором.
Основные действия подписаны; перевод и технические сведения отделены от
микрофона, динамика, удержания и клавиатуры. В настройках звука повседневные
параметры отделены от дополнительных. Логика SIP, сессий, согласий, маршрутизации
и отправки SMS не заменяется демонстрационными данными.

Нативные UI-тесты проверяют поиск, переключение списков, ввод номера, состояния
кнопок, явный выбор получателя и входа; отдельно рендерятся узкий экран, тёмная
тема и крупный текст. Тестовые скриншоты используют синтетические данные и не
подтверждают звук, реальные вызовы или отображение на всех физических устройствах.

### Личный приоритет получения звонков (0.6.1)

**Настройки → Мой приоритет звонков** — дополнительные личные предпочтения,
не отказ от других линий. Доступны область линии, устройства, типа шлюза,
подтверждённой голосовой SIM и всех линий; необязательно можно уточнить звонящего.
Трёхшаговый редактор сохраняет правило на сервере с проверкой версии, а проверка
показывает серверный расчёт только вашего приоритета, не вымышленную команду.

Личное распределение требует включённого исполнителя HI-RO Server/Asterisk:
приложение показывает фактический серверный статус, а не считает сохранение
активацией. Поддерживается безопасная смена общего SIP-аккаунта на отдельный
аккаунт сессии. При равенстве звонок получают одновременно; занятость и отсутствие
ответа переводят его к резерву. Старым клиентам нужно обновиться, браузеру —
переподключиться. Очередь обращений, исходящие линии и приём SMS — отдельные
настройки. Подробнее: [личные приоритеты](docs/RECEPTION_PRIORITY.md).

### Клиенты и маршрутизация (пилот)

Четыре основных раздела: **Звонки · Сообщения · Клиенты · Настройки**.
Во вкладке «Клиенты» отдельно показаны **Клиенты команды** и **Мои контакты**.
Личная адресная книга хранится на сервере только для вошедшего пользователя.
Синхронизация всей книги включается только после отдельного согласия и разрешения
READ_CONTACTS; можно вместо неё импортировать выбранные записи. Контакты Android
не изменяются. Номера нормализуются в международный формат; неоднозначные короткие
номера не угадываются. Работа синхронизации после остановки приложения Android
не гарантируется. Выключение не удаляет уже сохранённые серверные контакты.

Публикация **одного** контакта для всей команды — отдельное действие с проверкой
данных и подтверждением. Автор привлечения записывается автоматически и не меняется
после обычного редактирования. Администратор может добавить внешнего клиента с
неуказанным автором. Эта отметка не назначает ответственного и не маршрутизирует звонок.
Снятие общего статуса сохраняет личную копию для пользователя и удаляет общие правила.
Требуется соответствующий модуль личных контактов HI-RO Server.

Правила входящих/исходящих можно назначить на линию, проверенную SIM,
устройство, тип шлюза или все линии. Более конкретное правило имеет преимущество
перед правилом типа независимо от числа приоритета. Общие правила меняет
администратор, клиентские — также менеджер. Устаревшие изменения не затирают
чужие настройки: приложение просит обновить данные.
Предпросмотр учитывает полный порядок сервера: область → правило клиента →
направление → число. Для исходящих нельзя сравнивать только число разных линий.

Для исходящего звонка доступны автоматический выбор или явная голосовая линия
и SIP-аккаунт нашей АТС. Нужен сервер с включённым модулем routing. SIM не
показывается как доступная только из-за наличия в SMS API: голосовой адаптер
должен реально поддерживать и подтверждать выбор. Приоритет входящих действует
в очереди сервера, не прерывает разговор и не делает занятую SIM многоканальной.
Голосовые линии выбираются в **Звонки → Набрать номер**, личный приём SMS —
в **Настройки → Какие SMS получаю**. Общий журнал звонков команды, подключение
операторов, мобильный ИИ и настройка провайдеров в приложении пока не реализованы.
Подробная карта экранов и ограничения: [редизайн 0.6](docs/MOBILE_REDESIGN.md).

### Остальные возможности

- входящие и исходящие SIP-вызовы;
- вход на выбранный self-hosted HI-RO Server через discovery API;
- соблюдение политики сервера: локальная учётная запись, OpenID Connect с обязательным PKCE или принудительный SSO-only;
- постоянная отзываемая сессия устройства и зашифрованное Android Keystore хранение её токена;
- автоматическое обновление короткого access token без повторного ввода пароля;
- сохранение входа при выключении телефона, истечении access token и отсутствии сети;
- системный экран вызова Android и фоновый foreground service;
- контакты, история звонков, SIP-сообщения и серверные SMS;
- двусторонние SMS через телефон-шлюз с долговечной серверной очередью;
- фоновая синхронизация входящих SMS, уведомления и счётчик непрочитанных;
- работа с локальным шлюзом по TCP без внешнего push-провайдера;
- голосовой аудиорежим Android (`VOICE_COMMUNICATION`);
- увеличенные OpenSL ES очереди для более устойчивого звука;
- безопасная проверка, загрузка и установка обновлений из GitHub Releases;
- интерфейс оператора на русском и английском языках.

## Архитектура

```text
Телефон-шлюз + SIM → HI-RO Phone Gateway / Asterisk → SIP/RTP → HI-RO Connect
```

HI-RO Connect — клиент менеджера. SIM-карта и Bluetooth HFP находятся на стороне шлюза, а приложение менеджера получает уже маршрутизированный SIP-вызов.

## Сборка

Требования:

- Android Studio или JDK 21;
- Android SDK 37.0;
- Android NDK `27.1.12297006`;
- CMake 3.22.1;
- Linux-пакеты `wget cmake make libtool m4 automake pkg-config unzip`.

Подготовка нативных библиотек:

```bash
git submodule update --init
make -C libbaresip-android download-sources
./scripts/apply-native-build-patch.sh
./scripts/pin-native-dependencies.sh
./scripts/apply-audio-patch.sh
make -C libbaresip-android libbaresip ANDROID_TARGET_ARCH=arm64-v8a
```

Скопируйте собранные заголовки и библиотеки из `libbaresip-android/distribution` в корневой каталог `distribution`, затем соберите приложение:

```bash
./gradlew :app:assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

Стабильные подписанные APK публикуются в [GitHub Releases](https://github.com/IgorNadein/hiro-connect-android/releases). Приложение проверяет обновления в разделе **О программе → Обновления** и перед установкой сверяет репозиторий, размер, контрольную сумму, package name, номер версии и сертификат. Схема публикации и необходимые GitHub Secrets описаны в [документации обновлений](docs/github-updates.md).

## Настройка

Репозиторий намеренно не содержит логинов, токенов или паролей рабочего шлюза. При первом запуске пользователь выбирает HI-RO Server, а приложение следует объявленной сервером политике входа. В режиме SSO-only оно сразу открывает провайдера организации и не показывает локальные поля. Локальный пароль не сохраняется; при OIDC-входе пароль вводится только на странице провайдера и не попадает в приложение. Сервер выдаёт бессрочную отзываемую сессию устройства; её токен хранится в зашифрованном виде через Android Keystore. Повторный вход требуется только после явного выхода, отзыва устройства администратором, блокировки пользователя либо потери защищённого хранилища приложения. SIP-аккаунт добавляется отдельно через меню **Аккаунты**; для локальной установки обычно нужны адрес шлюза, внутренний номер менеджера, отдельный SIP-пароль и транспорт TCP.
